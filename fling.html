Fling

Quick capture for iPhone. Type or dictate a note, swipe up, and Fling saves it as plain Markdown to iCloud Drive, a Files folder, or an automation webhook.

Support

Need help with Fling? Email sober@duck.com with your device model, iOS version, and what you were trying to do.

Common Questions

Where do my notes save?

By default, Fling saves notes to iCloud Drive. You can also choose any Files-compatible folder in Settings.

What happens if my destination is unavailable?

Fling tries to save the note locally in the Files app container so your note is not lost.

Do I need an account?

No. Fling does not have accounts, ads, tracking, or third-party analytics SDKs.

How do I use webhook delivery?

Open Settings, tap Connect Webhook, then paste a Discord webhook URL or a Fling connection link from your automation bridge or receiver. Fling previews the destination and verifies the link before saving it.

Webhooks

Fling posts one HTTP request per note to each webhook destination. This is the contract a receiver can rely on (schema 2.0, Fling 1.2). Paste any HTTPS URL, a Discord or Slack webhook, or a legacy connection link; pick how it's secured and what your server receives; then Fling sends a real test request and lets you save once your server answers 2xx.

Request

POST <your URL> over HTTPS (plain http only for localhost, 127.0.0.1, ::1 and *.local). IP-literal hosts and URLs with credentials are refused; redirects are not followed.

Headers on every request:

Content-Type: <per body format, below>
User-Agent: Fling/<app version> (ios|macos)
X-Fling-Event: note | test
X-Fling-Schema: 2.0
X-Fling-Delivery: <uuid>          same value on the retry = idempotency key

Authentication, one of (chosen in the app):

Authorization: Bearer <token>                       bearer token (also legacy connection links)
<Your-Header>: <value>                              custom header, e.g. X-API-Key
X-Fling-Timestamp: <unix seconds>                   signing secret
X-Fling-Signature: v1=<hex HMAC-SHA256(secret, "<timestamp>.<raw body bytes>")>

Legacy connection links (…?token=…&slug=…) also send X-Fling-Project: <slug> and project_slug in the body. Extra headers configured in the app are sent as given; they may not shadow Authorization, Content-Type, Content-Length, Host, User-Agent or X-Fling-*.

Response

Any 2xx means "stored". Fling retries once after a timeout, a connection error or a 5xx, about 1.5 s later, with the same X-Fling-Delivery; a 4xx is final. The retry is a fresh request (a new signature timestamp).

X-Fling-Event: test is the setup check: a real request with a fixed sample note. Answer 2xx and store nothing.

Body formats

JSON (application/json), the default:

{
  "schema_version": "2.0",
  "event": "note",
  "id": "11111111-2222-3333-4444-555555555555",
  "created_at": "2026-10-15T08:15:30Z",
  "timezone": "Asia/Singapore",
  "title": "Pitch idea",
  "text": "Pitch idea\n\nA focus timer that only counts the minutes you actually focus",
  "description": "A focus timer that only counts the minutes you actually focus",
  "format": "markdown",
  "input_method": "typed",
  "source": { "platform": "macos", "app_version": "1.2" },
  "folder": "ideas",
  "project_slug": "personal_notes",
  "attachments": [ { "name": "note-1.png", "type": "image/png", "size": 48213, "part": "files[0]" } ]
}
  • description is omitted for one-line notes; folder only when the note was filed into a sub-folder; project_slug only for legacy connection links; attachments only with images.
  • input_method is typed, voice or mixed.
  • Every schema 1.x field is still present with the same meaning; 2.0 adds event, source, folder, attachments.
  • Images ("Include images" on): the request becomes multipart/form-data with a payload_json part (the JSON above) followed by files[0], files[1]… parts carrying the image bytes (image/png, image/jpeg, image/gif). Templates, form and Markdown bodies never carry images.

Markdown (text/markdown; charset=utf-8): the note text, nothing else. The first line is the title.

Form (application/x-www-form-urlencoded; charset=utf-8): fields schema_version, event, id, created_at, timezone, title, text, format, input_method, platform, app_version, plus description, folder, project_slug when present.

Template (application/json when the template starts with { or [, else text/plain): your template with placeholders replaced: {{title}} {{text}} {{description}} {{created_at}} {{id}} {{timezone}} {{input_method}} {{platform}} {{folder}} {{event}}. In a JSON template the values are JSON-string-escaped. Slack preset: {"text": "{{text}}"}.

Discord

Paste the channel's webhook URL. Fling keeps the token in the Keychain, verifies with a quiet GET, posts with mentions disabled, and sends images as attachments (8 MiB, 10 files). Notes over 2000 characters fall back to the Files app instead of being truncated.

Verifying a signature

Node (Express with express.raw({ type: '*/*' }) so req.body is the raw bytes):

const crypto = require("crypto");
app.post("/fling", (req, res) => {
  const ts = req.get("x-fling-timestamp");
  const sig = (req.get("x-fling-signature") || "").replace(/^v1=/, "");
  const expected = crypto.createHmac("sha256", process.env.FLING_SECRET)
    .update(`${ts}.`).update(req.body).digest("hex");
  const fresh = Math.abs(Date.now() / 1000 - Number(ts)) < 300;
  const ok = fresh && sig.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(sig, "hex"), Buffer.from(expected, "hex"));
  if (!ok) return res.sendStatus(401);
  if (req.get("x-fling-event") === "test") return res.sendStatus(204);
  const note = JSON.parse(req.body);
  // store note …
  res.sendStatus(204);
});

Python (FastAPI):

import hmac, hashlib, os, time
from fastapi import FastAPI, Request, Response

app = FastAPI()

@app.post("/fling")
async def fling(request: Request):
    body = await request.body()
    ts = request.headers.get("x-fling-timestamp", "0")
    sig = request.headers.get("x-fling-signature", "").removeprefix("v1=")
    expected = hmac.new(os.environ["FLING_SECRET"].encode(), f"{ts}.".encode() + body, hashlib.sha256).hexdigest()
    if abs(time.time() - int(ts)) > 300 or not hmac.compare_digest(sig, expected):
        return Response(status_code=401)
    if request.headers.get("x-fling-event") == "test":
        return Response(status_code=204)
    note = await request.json()
    # store note …
    return Response(status_code=204)

Cloudflare Worker: read await request.text() for the body, compute the HMAC with crypto.subtle (HMAC, SHA-256), compare hex.

Reproducing a request

The setup sheet's Copy as curl gives the exact request with secrets as $FLING_* variables; Copy setup prompt for your AI gives a brief an assistant can build a receiver from. Settings keeps the last ten deliveries per webhook (time, status, latency, the first 200 characters of the response); headers and bodies are never stored.

Privacy Policy

Last updated: June 13, 2026

This privacy policy describes how 47 Summers LLC ("we", "us") handles information in connection with Fling.

Summary

Fling is a quick-capture app for saving notes as plain Markdown files. Fling does not require an account, does not include ads, and does not track you across apps or websites.

What Fling Stores

  • App settings: Fling stores preferences on your device, such as sound, haptics, text size, selected destination, and clear-gesture settings.
  • Folder access: If you choose a custom folder, Fling stores a security-scoped folder bookmark so it can keep saving notes to that folder.
  • Webhook connection: If you connect a webhook, Fling stores the secret token in the iOS Keychain and stores non-secret connection details, such as the destination name and URL, in app settings.
  • Draft text: If you leave an unfinished note, Fling may store that draft locally so it can be restored when you reopen the app.

Notes And Destinations

By default, Fling saves notes to the app's iCloud Drive folder. iCloud syncing is handled by Apple and your Apple ID settings.

If you choose a folder through the Files picker, Fling saves notes to that folder. That folder may be local to your device or provided by another app or cloud storage service.

If you connect a webhook, Fling sends note content to the webhook URL you configured. The destination service may process or store that content according to its own policies. Fling does not operate the webhook destination unless you host it yourself.

If a configured destination is unavailable, Fling tries to save the note locally in the Files app container so the note is not lost.

Microphone And Speech Recognition

Fling asks for microphone and speech recognition permission only if you use voice dictation. Dictation is handled through Apple's system speech-recognition services. Fling does not record, sell, or use your voice for advertising.

Anonymous Milestone Counts

Fling may send a small anonymous milestone event when an install reaches counts such as 10, 100, 500, or 1000 successful Flings. These events help us understand whether people are actually using the app and whether early users should receive future Plus access.

Milestone events include an app-scoped random install identifier, the milestone number, app version, build number, and timestamp. They do not include note text, filenames, folder names, webhook URLs, Apple ID, email, contacts, location, or device model.

If a milestone cannot be sent, Fling keeps it on your device and retries later. Milestone events are not used for advertising or tracking across other apps or websites.

Local Network

Fling asks for local network permission only if you connect a local webhook endpoint, such as a development server on your own network.

What Fling Does Not Do

  • require an account
  • show ads
  • track you across apps or websites
  • sell personal data
  • upload your notes to a Fling-owned server

Deleting Your Data

You can delete saved notes from the folder where they were saved, including iCloud Drive, a custom folder, or the local Files app container.

You can disconnect a webhook in Settings. You can remove local Fling data by deleting the app from your device. Notes that were already saved to iCloud Drive or another folder may remain in those locations until you delete them there.
